# Architecture and Design Philosophy

Aven represents a paradigm shift from traditional imperative and functional programming to **declarative relational invariant systems**.

---

## 1. The Core Problem: Function Directionality in Engineering

In conventional programming languages (Rust, C, Python, Go), algorithms are defined as one-way functions:

```python
# In conventional languages: 3 separate functions for 1 physical law
def force(mass, acceleration):
    return mass * acceleration

def mass(force, acceleration):
    return force / acceleration

def acceleration(force, mass):
    return force / mass
```

In physical engineering, industrial telemetry, aerospace, and datacenter infrastructure, this directional pinning causes massive technical debt:
1. **Combinatorial Explosion:** A system with $N$ interconnected variables needs a separate function for every combination of known and unknown variables a deployment might see.
2. **Duplicated Verification:** Validating bounds (e.g. $a \le 9.8\,\text{m/s}^2$) must be reimplemented across every single directional permutation.
3. **Sensor Dropouts:** If a sensor fails, the entire procedural execution graph crashes unless fallback branches are manually coded.

### The Aven Solution: Relations
In Aven, you write the mathematical invariant once:

```aven
signal force        : N
signal mass         : kg
signal acceleration : m/s^2

relation Mechanics {
    force = mass * acceleration
}
```

When observed inputs arrive (e.g., `force = 100`, `acceleration = 9.8`), Aven inspects the dependency graph, finds the unknown (`mass`), and solves the equation for it with Newton–Raphson.

## 2. Zero-Dependency Pure Rust Philosophy

The entire `avenc` toolchain is written in standard library Rust (`std`) with **zero third-party crate dependencies**:

- **No Third-Party Parsers (Nom/Pest):** Custom recursive descent parser with precise span diagnostics.
- **No Third-Party Serialization (Serde):** Custom pure-`std` JSON tokenizer and deserializer.
- **No Third-Party Math/Optimization Libraries:** Custom symbolic differentiator and guarded Newton-Raphson relaxation engine.
- **No Third-Party Cryptography (Ring/Sha2):** Native FIPS 180-4 standard SHA-256 implementation in pure Rust.
- **No Third-Party Network Stacks (Tokio/Reqwest):** Native `std::net::TcpStream` and socket buffer management.

### Why Zero Dependencies?
1. **Auditable Security:** Eliminates supply-chain vulnerabilities, malicious package dependencies, and complex build trees.
2. **Fast Compilation:** A clean build has nothing to download or compile but `avenc` itself (12 s debug, 19 s release on a 4-vCPU Linux container).
3. **Portability:** `avenc` builds wherever Rust's standard library does (developed on Windows, tested on Linux in CI). Bare-metal targets are served by the C it generates, not by the compiler itself.

## 3. Mathematical Solving Engine

`avenc` settles equations in three ways, chosen per equation from what is known:

### Forward Evaluation
When every variable on the right-hand side of `lhs = rhs` is known, the right side is evaluated directly (`... <- forward eval` in the trace).

### One-Unknown Newton–Raphson
When an equation has exactly one unknown that is not its left-hand side, Aven solves $g(x) = \text{lhs} - \text{rhs}(x) = 0$ with Newton's method, using the symbolic derivative of the right-hand side (`... <- backward Newton`). No equation is rearranged by hand: `mass` in `force = mass * acceleration` is found the same way as a variable inside `exp`, `sqrt` or `ceil`.

$$x_{n+1} = x_n - \frac{g(x_n)}{g'(x_n)}$$

### Coupled Newton–Raphson
When several unknowns are linked through several equations, Aven solves them together with multidimensional Newton–Raphson, building the Jacobian from symbolic partial derivatives (`[coupled] ... <- multidim Newton`). Under-determined systems are reported with their free variables instead.

Undefined operations (division by zero, `sqrt` of a negative, `ln` of a non-positive value, non-finite results) are evaluation errors. Models can keep the solver away from them with small offsets, as `flight_mesh_ipc.aven` does:
```aven-fragment
safe_temp_k = ambient_temp_k + 0.0001
speed_of_sound_ms = sqrt(1.4 * 287.058 * safe_temp_k)
mach_number = velocity_ms / (speed_of_sound_ms + 0.0001)
```

## 4. Direction Pinning & C Code Generation (`avenc emit-c`)

While the relational solver is ideal for dynamic telemetry and exploration, safety-critical embedded systems (PLCs, automotive ECUs, flight controllers) cannot tolerate runtime solver relaxation.

Aven solves this via **Direction Pinning**:
1. When all input variables are fixed or declared in a `forward` block, `avenc` performs a topological sort on the equation dependency graph.
2. The compiler verifies there are zero circular dependencies.
3. `avenc emit-c` outputs branchless C99 with no solver runtime. From `examples/server_capacity.aven`:

```c
/* Generated by avenc -- direction-pinned, solver-free */
static void aven_ProductionProfile(double avg_latency_ms, double avg_payload_kb, double framing_overhead_ratio, double os_kernel_ram_mb, double ram_per_worker, double reqs_per_second, double socket_buffer_mb, double target_utilization, double* out_raw_workers, double* out_allocated_workers, double* out_total_ram_needed, double* out_payload_gbps, double* out_wire_rate_gbps) {
    const double raw_workers = ((reqs_per_second * avg_latency_ms) / 1000.0);
    const double allocated_workers = aven_ceil((raw_workers / target_utilization));
    const double total_ram_needed = ((allocated_workers * (ram_per_worker + socket_buffer_mb)) + os_kernel_ram_mb);
    const double payload_gbps = (((reqs_per_second * avg_payload_kb) * 8.0) / 1000000.0);
    const double wire_rate_gbps = (payload_gbps * framing_overhead_ratio);
    *out_raw_workers = raw_workers;
    /* ... one assignment per output ... */
}
```

## 5. Provenance & Freshness Enforcement

Every computed fact is stored in an immutable, append-only **Fact Ledger**:
- **SHA-256 Hash Chain:** Each fact links to the previous one, so any edit, deletion, reordering or truncation is detected by `avenc verify-ledger` (and with a key, each fact is HMAC-signed).
- **Time-to-Live (`ttl_ms`):** Telemetry vectors carry freshness timeouts. If an upstream sensor stops reporting, `is_stale` is flagged, and Aven halts downstream decisions with `DECISION BLOCKED` / `HOLD` rather than executing on stale ghost data.
