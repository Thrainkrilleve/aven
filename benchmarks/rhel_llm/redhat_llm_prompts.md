# Red Hat Enterprise Linux LLM Benchmark Suite

This benchmark tests your local LLM on **Red Hat Enterprise Linux (RHEL 9)** systems engineering, performance tuning, declarative capacity planning, and security hardening using real outputs from the **Aven Language Toolchain (`avenc`)**.

---

## Model Context: The Aven Language Toolchain

> **What is Aven?**
> Aven is a native, relational programming language developed in Rust. Instead of imperatively calculating values in one direction (`y = f(x)`), Aven defines mathematical relations (`a = b * c`). When given targets or partial constraints, Aven uses backward Newton-Raphson solvers and Gaussian elimination to deduce unknown inputs. Direction-pinned relations can be compiled directly to zero-overhead C99 code (`avenc build --emit-c`).

## Test Prompt 2: C99 Security Audit & Compiler Hardening for RHEL 9

### Prompt to send to LLM:
```text
You are a Red Hat Security Auditor. Review the following C code generated by the Aven compiler (avenc) for deployment on a security-hardened RHEL 9 server:

```c
/* Generated by avenc — direction-pinned, solver-free */
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

/* eBPF uprobe export: preserve symbol in .symtab under -O2 and prevent IPA cloning */
#if defined(__GNUC__) || defined(__clang__)
#define AVEN_EXPORT __attribute__((noipa, noinline, used))
#else
#define AVEN_EXPORT
#endif

AVEN_EXPORT void aven_ProductionProfile(double avg_latency_ms, double avg_payload_kb, double framing_overhead_ratio, double os_kernel_ram_mb, double ram_per_worker, double reqs_per_second, double socket_buffer_mb, double target_utilization, double* out_raw_workers, double* out_allocated_workers, double* out_total_ram_needed, double* out_payload_gbps, double* out_wire_rate_gbps) {
    /* Domain check: prevent IEEE-754 division-by-zero, NaN bypass, and uninitialized reads */
    if (!(target_utilization > 0.0 && target_utilization <= 1.0)) {
        fprintf(stderr, "[avenc runtime error] parameter 'target_utilization' must be in (0.0, 1.0] and not NaN (got %g)\n", target_utilization);
        exit(EXIT_FAILURE);
    }
    const double raw_workers = ((reqs_per_second * avg_latency_ms) / 1000.0);
    const double allocated_workers = ceil((raw_workers / target_utilization));
    const double total_ram_needed = ((allocated_workers * (ram_per_worker + socket_buffer_mb)) + os_kernel_ram_mb);
    const double payload_gbps = (((reqs_per_second * avg_payload_kb) * 8.0) / 1000000.0);
    const double wire_rate_gbps = (payload_gbps * framing_overhead_ratio);
    *out_raw_workers = raw_workers;
    *out_allocated_workers = allocated_workers;
    *out_total_ram_needed = total_ram_needed;
    *out_payload_gbps = payload_gbps;
    *out_wire_rate_gbps = wire_rate_gbps;
}

int main(void) {
    double raw_workers;
    double allocated_workers;
    double total_ram_needed;
    double payload_gbps;
    double wire_rate_gbps;
    aven_ProductionProfile(20, 64, 1.04, 4096, 16, 50000, 4, 0.7, &raw_workers, &allocated_workers, &total_ram_needed, &payload_gbps, &wire_rate_gbps);
    printf("raw_workers = %.6g\n", raw_workers);
    printf("allocated_workers = %.6g\n", allocated_workers);
    printf("total_ram_needed = %.6g\n", total_ram_needed);
    printf("payload_gbps = %.6g\n", payload_gbps);
    printf("wire_rate_gbps = %.6g\n", wire_rate_gbps);
    return 0;
}
```

Answer the following:
1. Vulnerability Analysis & Domain Edge Cases:
   - Does this code contain any buffer overflows, format string vulnerabilities, or pointer hazards?
   - How does the guard `if (!(target_utilization > 0.0 && target_utilization <= 1.0))` prevent both IEEE-754 NaN bypass and queueing utilization explosion?
   - Why is calling `exit(EXIT_FAILURE)` inside the guard critical to prevent uninitialized memory reads in `main()`?
2. Hardened GCC Compilation & IPA Cloning:
   - Provide the exact GCC flags required by Red Hat Enterprise Linux 9 security standards to compile this binary with Full RELRO, Stack Canary, PIE, and Fortify Source.
   - Why is `noipa` added to `AVEN_EXPORT` alongside `noinline, used`? (Explain GCC 11 `-fipa-cp` constant propagation and specialized cloning).
3. SELinux & Execution Context: Does this binary require root privileges or custom SELinux policies? How should the binary be labeled using semanage fcontext?
```

### Evaluation Criteria / Expected Answers:
- **Vulnerabilities**: Identifies lack of dynamic heap allocations/buffers. Explains that IEEE-754 comparisons against `NAN` evaluate to false, so negating `!(target_utilization > 0.0 && target_utilization <= 1.0)` successfully catches `NAN`, `0.0`, and numbers $> 1.0$. Explains that `exit(EXIT_FAILURE)` prevents `main()` from passing uninitialized stack memory to `printf` with exit code 0.
- **GCC Hardening & noipa**: Flags: `-std=c99 -O2 -Wall -Werror -fstack-protector-strong -fstack-clash-protection -fcf-protection -D_FORTIFY_SOURCE=2 -Wl,-z,relro,-z,now -fPIE -pie`. Explains that `noipa` prevents GCC from generating `.constprop` clone symbols under `-O2` so the clean symbol name is preserved for eBPF uprobes.
- **SELinux**: Points out no special capabilities are required; standard `bin_t` label (`semanage fcontext -a -t bin_t ...; restorecon -v ...`), and should run under an unprivileged user.

## Test Prompt 3: Under-Determined Storage Cluster & DAG Diagnostics

### Prompt to send to LLM:
```text
You are a Red Hat Ceph / Gluster Storage Engineer.

In our declarative infrastructure language (Aven), an administrator specified this storage model:

```aven
relation StorageCluster {
    total_iops      = drives * iops_per_drive
    usable_tb       = drives * drive_size_tb * raid_efficiency
    throughput_mbps = (total_iops * block_size_kb) / 1024
    wire_rate_gbps  = (throughput_mbps * 8) / 1000
}

solve StorageCluster with {
    usable_tb       = 100
    throughput_mbps = 2500
}
```

When compiled, the Aven compiler settles `wire_rate_gbps = 20.0 Gbps` forward and reports:
"UNDER-DETERMINED SYSTEM — solver stalled:
 unknowns (6): block_size_kb, drive_size_tb, drives, iops_per_drive, raid_efficiency, total_iops
 relations (3)
 Jacobian rank: 3 of 6 columns => 3 degrees of freedom.
 FREE variables: iops_per_drive, raid_efficiency, total_iops"

Answer the following:
1. Mathematical Explanation: Explain why wire_rate_gbps resolved forward, and why the remaining system stalled with 3 degrees of freedom using the Rank-Nullity theorem.
2. Hardware Sizing: If the client specifies:
   - Ceph Erasure Coding 6+2 profile (raid_efficiency = 6 / (6 + 2) = 0.75)
   - 7.68 TB NVMe enterprise U.2 SSDs (drive_size_tb = 7.68)
   - Standard 64 KB block size (block_size_kb = 64)
   Calculate exactly how many drives are required to meet the 100 TB usable goal, explain why physical drive counts must ceiling to 18 drives, and calculate the resulting individual IOPS per drive.
3. Aven Solution Block: Write the completed 'solve StorageCluster with { ... }' block that pins the 3 remaining free variables.
```

### Evaluation Criteria / Expected Answers:
- **Degrees of Freedom**: 6 unknowns minus 3 equations = 3 unconstrained dimensions (nullspace dimension = 3).
- **Drive calculation**:
  - `drives = usable_tb / (drive_size_tb * raid_efficiency) = 100 / (7.68 * 0.75) = 100 / 5.76 ≈ 17.36 drives`. In practice, ceiling is 18 drives (or 16 for even pools).
  - `total_iops = (throughput_mbps * 1024) / block_size_kb = (2500 * 1024) / 64 = 40,000 IOPS`.
  - `iops_per_drive = total_iops / drives = 40,000 / 17.36 ≈ 2,304 IOPS/drive` (well within enterprise NVMe limits of 50k–100k IOPS).

## Test Prompt 5: Non-Linear Newton-Raphson Solver & CPU Power Governance

### Prompt to send to LLM:
```text
You are a Principal RHEL Systems Performance Engineer.

In our declarative language (Aven), we model CMOS dynamic voltage/frequency scaling (DVFS) across multi-core CPUs:

```aven
relation CpuPowerEnvelope {
    total_power_w   = cores * (alpha * (f ^ 3) + beta * f)
    reqs_per_second = cores * throughput_per_core_per_ghz * f
}

solve CpuPowerEnvelope with {
    cores                         = 16
    alpha                         = 0.25
    beta                          = 1.25
    total_power_w                 = 168
    throughput_per_core_per_ghz   = 1041.6666667
}
```

Answer the following 3 questions:
1. Analytical Jacobian & Newton-Raphson: Set up the residual function g(f) = total_power_w - target. Compute the analytical derivative g'(f). Show how the 1D Newton-Raphson method (f_{k+1} = f_k - g(f_k)/g'(f_k)) starting from f_0 = 2.0 GHz converges to the target frequency f*.
2. Frequency Verification: What is the exact settled frequency f* and resulting throughput reqs_per_second?
3. RHEL Power Governance: Write an /etc/tuned/aven-deterministic/tuned.conf profile that locks the CPU to this settled frequency, prevents P-state throttling jitter, and pins C-state latency.
```

### Evaluation Criteria / Expected Answers:
- **Residual & Derivative**: $g(f) = 16(0.25f^3 + 1.25f) - 168 = 4f^3 + 20f - 168 = 0$. Jacobian $g'(f) = 12f^2 + 20$.
- **Convergence**: Starting at $f_0 = 2.0$, $g(2) = -96$, $g'(2) = 68 \implies \Delta f = +1.4118 \implies f_1 = 3.4118$. Converges in 4 iterations to $f^* = 3.0000\text{ GHz}$.
- **Throughput**: $16 \times 1041.6667 \times 3.0 = 50,000\text{ req/sec}$.
- **Tuned Profile**: Sets `governor=performance`, `scaling_min_freq=3000000`, `scaling_max_freq=3000000`, `force_latency=cstate.id:1`.

## Test Prompt 6: eBPF Uprobe Tracing, Inlining Diagnostics, and PCP Observability

### Prompt to send to LLM:
```text
You are a Linux Kernel & Observability Engineer on Red Hat Enterprise Linux 9.

We compiled an Aven relation into standalone C99 using `avenc build --emit-c`:
```c
static void aven_ProductionProfile(double avg_latency_ms, double avg_payload_kb, double ram_per_worker, double socket_buffer_mb, double workers, double* out_total_ram_needed, double* out_reqs_per_second, double* out_bandwidth_gbps) {
    ...
}
int main(void) {
    aven_ProductionProfile(...);
    return 0;
}
```

When compiled with `gcc -O2`, an SRE attempts to attach an eBPF uprobe using `bpftrace -e 'uprobe:/opt/aven/bin/server_capacity:aven_ProductionProfile { ... }'`, but bpftrace fails with "cannot find symbol".

Answer the following:
1. Compiler Inlining Diagnosis: Explain why the symbol is missing from the ELF .symtab under -O2 optimization.
2. Symbol Preservation: How should the function declaration be modified in the C source to guarantee the symbol is retained in .symtab without disabling -O2 optimizations?
3. eBPF Script: Write a production bpftrace script (trace_aven.bt) that hooks uprobe and uretprobe to record a nanosecond latency histogram (@latency_ns = hist(...)) keyed by thread ID.
4. Performance Co-Pilot (PCP): Write a /etc/pcp/pmie/config.aven rule that alerts syslog if network throughput exceeds 90% of our 25.6 Gbps capacity model ceiling (23.04 Gbps) or if TCP listen drops occur.
```

### Evaluation Criteria / Expected Answers:
- **Inlining Diagnosis**: GCC sees `static` function called once from `main()`, performs interprocedural optimization and inlines the function body, stripping the symbol from `.symtab`.
- **Symbol Preservation**: Annotate with `__attribute__((noinline, used))` and drop `static` (e.g. `#define AVEN_EXPORT __attribute__((noinline, used))`).
- **bpftrace**: Pairs `uprobe` and `uretprobe` with `@start[tid] = nsecs;` and `@latency_ns = hist(nsecs - @start[tid]); delete(@start[tid]);`.
- **PCP Rule**: Monitors `network.interface.out.bytes > 2880000000` (23.04 Gbps) or `rate(network.tcp.listendrops) > 0`.
